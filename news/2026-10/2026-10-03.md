### 1. Microsoft「ThinkingBox」公開 — ツール呼び出しではなく「データベースの最終状態」でLLMエージェントを評価するベンチマーク

| 項目 | 内容 |
|------|------|
| ソース | [Hugging Face Blog (Microsoft)](https://huggingface.co/blog/microsoft/thinkingbox) |
| 公開日 | 2026-10-03 |
| 重要度 | ⭐⭐⭐ |

**概要**: Microsoft Copilot Studioチームが、LLMエージェントの信頼性を測る新ベンチマーク「ThinkingBox / ThinkingBox-Bench」を公開した。応答文やツール呼び出しの形式正しさではなく、実行後にデータベースへ残った**最終状態と副作用**を採点対象とする点が特徴。小売・自動車保険・旅行・ネオバンク・コンサルティングの5領域507のステートフルな業務ワークフローを各20回、クリーンなバックエンド状態から独立実行し、12モデル・計12万1,680試行をpass@1 / pass@20 / 20回全成功(20/20)の3指標で評価した。

**詳細ポイント**:
- pass@1の総合首位はClaude Opus 5.5（67.16%）、オープンウェイト最強はKimi-K3（57.37%、小売ドメインでは82.24%で全モデル首位）
- 「1回の成功」と「毎回の成功」は大きく乖離: Kimi-K3は93.89%のタスクに少なくとも1回成功するが、20/20達成はわずか13.41%。一方Claude Opus 5は47.53%（241タスク）を毎回成功させた
- 失敗事例の67.24%は「正常終了しエラーも報告していない」ように見えるにもかかわらず、誤ったフィールド値（77.61%）・意図しない副作用（43.30%）・必須作用の欠落（25.36%）を含んでいた。失敗の79.9%は推論よりツール操作・リトライ系

**なぜ重要か**: リーダーボードのpass@1では見えない「本番で使えるか」の乖離を実行可能な検証コードで定量化した初の大規模試みであり、エージェント選定の軸を「能力」から「一貫性(consistency)」へ移すものだ。企業がエージェントにDBを触らせる以上、20/20レートを実装のデザイン入力にすべきという提言は実務的な示唆が大きい。

**関連キーワード**: LLMエージェント評価, ベンチマーク, pass@k, 一貫性, OpenEnv, Microsoft

### 2. 単体写真から編集可能な3Dシーンを構築する「LEGO-Anything」— しかしエージェントは正しさを自己検証できない

| 項目 | 内容 |
|------|------|
| ソース | [The Decoder](https://the-decoder.com/ai-agents-build-3d-scenes-from-photos-but-have-no-idea-if-they-got-it-right/) |
| 公開日 | 2026-10-03 |
| 重要度 | ⭐⭐⭐ |

**概要**: メリーランド大学とAWSの研究チームが「LEGO-Anything」を公開した。コーディングエージェントが1枚の写真からBlenderの実行可能プログラムを書き、実行→結果確認→修正を繰り返して編集可能な3Dシーンを構築する「Image-to-Code」手法だ。付属ベンチマークLEGO-Bench（104シーン208画像、443アセット）ではGPT-6 Astraが屋内53.4%・屋外39.6%と最高成績だった一方、エージェントは自分の生成物の幾何学的正確性を偶然水準以下の精度しか自己判定できず、改善と改悪を繰り返す実態が明らかになった。

**詳細ポイント**:
- 6つのGPT構成すべてがほぼ毎回「動くシーン」を提出したが、精度は最高53.4%から約15%までばらつき。推論予算を増やすとAstraのオフィス系サブセットは32.3%→61.8%に向上
- 失敗パターンは初手の精度不足・以前の進捗を打ち消す修正・自己評価の信頼性欠如。GPT-6 Astraでも処理後半に自シーンを33.9%→4.4%まで改悪した例が記録された
- 自己判断を具体的計測に置き換える「LEGO-Plugin」を追加すると、訓練なしで全6モデルが改善（弱いモデルで最大62.7%増）

**なぜ重要か**: 反復改善型エージェントの「自己評価ループ」の限界を定量化した稀有な研究で、外部フィードバック（測定ベース検証）の必須性を実証した。同日のThinkingBox結果とも整合し、エージェント設計における検証機構の標準化が急務であることを示す。

**関連キーワード**: LEGO-Bench, Image-to-Code, Blender自動化, 自己評価の限界, GPT-6 Astra

### 3. DeepMind研究者らが「人工共生的知能」を提唱 — シンギュラリティに代わるビジョン

| 項目 | 内容 |
|------|------|
| ソース | [The Decoder](https://the-decoder.com/deepmind-researchers-propose-artificial-symbiotic-intelligence-as-an-alternative-to-the-singularity/) |
| 公開日 | 2026-10-03 |
| 重要度 | ⭐⭐ |

**概要**: Google DeepMindのエッセイでBenjamin Bratton、Blaise Agüera y Arcas、James Manyikaらが、単一の超知能が自己改良を繰り返す「シンギュラリティ」の対案として「人工共生的知能（Artificial Symbiotic Intelligence）」を提案した。AGIは人間とAIエージェントが協働する社会システムから創発するという立場で、課題は孤立した機械知能の構築ではなく、エージェント・人間・接続システムのネットワークの協調と統治だと主張する。

**詳細ポイント**:
- 論拠の1つは実証研究「Reasoning Models Generate Societies of Thought」で、DeepSeek-R1やQwQ-32Bの推論トレース解析から、推論モデルが訓練から自発的に「内部討議・視点交代・異論の調停」のような複数視点的挙動を発達させると示したもの
- エージェントを「モデル・役割・記憶・ツール・スキルの一時的な集合体（assemblage）」と再定義し、人格を持つ実体ではなくswarm（群れ）として扱うべきと論じる
- 個々のモデルより機関（institution）の設計が重要で、アライメントも固定値の押し付けではなく継続的交渉として再定義すべきと提言。オーケストレーションハーネスが「より賢い」単一モデルを上回る現象を傍証として挙げる

**なぜ重要か**: マルチエージェント・オーケストレーションが実務で単一モデルを上回り始めた現在、その動向に理論的枠組みと統治ビジョンを与える文書だ。DeepMind内部からシンギュラリティ志向に代わる枠組みが出てきたことは、AGI開発の目標設定と政策・研究資金の方向付けの多様化を示す。

**関連キーワード**: Artificial Symbiotic Intelligence, マルチエージェント, オーケストレーション, エージェント統治, 人機共生

### 1. Meta「Muse」のエージェンティック・ショッピング実態 — Stripe/Shopify連携で手数料収益化へ、Amazonは遮断

| 項目 | 内容 |
|------|------|
| ソース | [CNBC](https://www.cnbc.com/2026/10/03/meta-muse-shopping-ai-agent.html) |
| 公開日 | 2026-10-03 |
| 重要度 | ⭐⭐⭐⭐ |

**概要**: MetaのパーソナルAIエージェント「Muse」の買い物機能の仕組みと課題をCNBCが詳報した。エージェントが小売サイトを巡回して商品を検索し、「承認カード」でユーザー確認後に決済まで完結できる。ショッピングは既にMuse最大の利用ドライバーとなっており、Walmart、Gap、Sephora、Expedia、Wayfair、Best Buyらとの「コネクタ」提携も発表済み。一方でAI動的価格設定への消費者の不信や、AmazonによるMuse利用のブロックなど業界を巡る対立も浮き彫りになった。

**詳細ポイント**:
- 決済はStripeの「Link」（使い捨てカード番号を生成し実カード情報を隠蔽）やShopify Shop Payと連携、PayPalも発表済みで提供準備中。ザッカーバーグCEOは取引から少額の手数料を得る方針を明言
- Amazonは「利用規約違反」（顧客認証情報の保存・アカウントデータのスクレイピング）を理由にMuseによる購入をブロック。エージェント主導ショッピングを巡る小売大手間の主導権争いが激化
- Morning Consult調査で米国人の59%がAI動的価格設定による価格つり上げを「重大な懸念」と回答。Walmart CEOは動的価格設定に個人情報を用いないとする公開書簡を発表。MuseはApp Store無料ランキング1位を獲得

**なぜ重要か**: エージェント経由の取引に手数料課金する収益モデルが具体化し、小売・決済・広告の収益構造再編が実戦段階に入った。「誰がエージェントを所有すれば消費者との関係を所有できるか」という覇権争いの行方を占う材料であり、プライバシー・価格差別の規制議論も同時進行する。

**関連キーワード**: Meta Muse, エージェンティックコマース, Stripe Link, Walmart, Amazon対立, 動的プライシング

### 2. Anthropic、Claude Codeに「Mods」システム導入 — JS/TSフックでコーディングエージェントを内部から改造可能に

| 項目 | 内容 |
|------|------|
| ソース | [The Decoder](https://the-decoder.com/claude-codes-new-mods-system-lets-developers-rewrite-the-ai-coding-tool-from-the-inside/) / 公式: [Claude Code Docs](https://code.claude.com/docs/en/plugins/mods/overview) |
| 公開日 | 2026-10-03 |
| 重要度 | ⭐⭐⭐ |

**概要**: AnthropicがClaude Code向けの「Mods」をリリースした。ツール内部で直接動くミドルウェアで、JavaScript / TypeScriptの関数がツール呼び出し・ユーザープロンプト・UI描画などのイベントにフックできる。チャット横のカスタムパネル追加、ツール呼び出しのインターセプト、全く新しいコマンドの実装が可能になり、組み込み機能の一部（`/diff`コマンド等）も既にModsとして実装されている。

**詳細ポイント**:
- CLI・デスクトップアプリで動作しVS Code拡張では部分的に対応。サンプルModsをGitHubで公開
- Modsはユーザーの権限で動作し**サンドボックス化されていない**——Anthropic自身が「信頼できるソースからのみインストールせよ」と警告。組織はロード可能なModsを制御可能
- 第1号の公式Modプラグイン「You Should Know」は、Claudeの出力を監視する別エージェントを起動し、ユーザーが見落としうる重要情報を検知すると"Heads up"メッセージを送る二段エージェント構成

**なぜ重要か**: コーディングエージェントを「改造不可の製品」から「イベントフックで拡張できるプラットフォーム」へ変えるもので、エージェントUI/UXとツール実行制御の標準化競争が本格化する。サンドボックス非対応という設計判断は、利便性とセキュリティのトレードオフを示す好例でもある。

**関連キーワード**: Anthropic, Claude Code, Mods, プラグイン, ツールフック, 開発者ツール
