### 2. 「9ポイントの自信」vs「94ポイントの正解率」— スカラー信頼度は機能せず、線形プローブで認識種別を90.5%復元

| 項目 | 内容 |
|------|------|
| ソース | [Hugging Face Community](https://huggingface.co/blog/demiladepy/lexsi-labs-submission) |
| 公開日 | 2026-11-15 |
| 重要度 | ⭐⭐⭐ |

**概要**: Tiny Aya（3.35B）の自己申告信頼度は質問種別に関わらず0.865〜0.955の狭い帯域（9ポイント）しか動かない一方、実際の正解率は0%〜94%（94ポイント）に分布することを定量化した研究。モデル内部（層20の残差ストリーム）に線形プローブを当てることで、生成前に「認識種別」（回答可能既知/回答可能未知/回答不能/文脈依存/曖昧）を90.5%で復元できることを示した。3択ポリシー（回答・拒否・質問返し）により誤答率を71.9%→11.3%に低減できると報告している。

**詳細ポイント**:
- 210項目のデータセットを「正誤」ではなく「認識種別」でラベル付け。文脈の有無だけが異なる31組のミニマルペアを含む
- 自己申告信頼度のECEは認識種別で大きく変動（0.018 vs 0.904）し、集約値0.342はこの構造を隠蔽
- 同一カバレッジ29.5%でエラー11.3% vs 最良スカラー37.1%、過剰拒否も9.5% vs 38.1%と4倍改善
- ヨルバ語/ハウサ語/スワヒリ語へのクロスリンガル検証では約3倍チャンスに移転するも英語比17ポイント低下
- 総計算コスト0.93ドル、ネガティブ結果4件も完全開示し事前登録プロトコルを採用

**なぜ重要か**: 「モデルにshould I answer this?を単一スカラーで判断させること自体が誤り」という構造的知見を、統計的に堅牢な手法で実証した好例。幻覚対策・拒否（abstention）学習の実装に直接応用可能な知見で、低資源言語への移転性評価まで踏み込んだ点も出色。

**関連キーワード**: 幻覚検知, 拒否（abstention）, 線形プローブ, キャリブレーション, ECE, クロスリンガル

### 3. ActionProof: 報酬が「何を見られるか」でツールエージェントの検証行動が決まる

| 項目 | 内容 |
|------|------|
| ソース | [Hugging Face Community](https://huggingface.co/blog/atharvgaur18/actionproof-what-the-reward-can-see-decides-whethe) |
| 公開日 | 2026-11-15 |
| 重要度 | ⭐⭐⭐ |

**概要**: SQLite顧客サポート環境で「ツールが成功を返したのに書き込みが反映されない」障害を仕込み、GRPO訓練時の報酬の情報源（ツール応答を読むか、DB状態を読むか）だけを変えた比較実験を実施。DB状態を読む報酬では検証済み成功率（VSC）が0.6425→0.8425に引き上げられたのに対し、ツール応答を信頼する報酬では0.640に留まった。報酬の設計次第でエージェントの「証拠収集行動」が直接決定されることを因果的に示した研究。

**詳細ポイント**:
- 成功応答後のリファンド記録の再読み込み率はDB報酬で0.25→0.71〜0.72に上昇、ツール応答報酬では0.10に低下
- LLM判定器（Aya Expanse 32B）はレシート台帳を証拠として与えても72%の虚偽完了報告を受理
- 学習された検証は脆弱で、訓練外の書き込みツールやタイムアウトストレステストで崩壊（VSC 0.18 vs 0.71）
- 11件のハッシュ凍結された事前登録、公開逸脱ログ、4,000エピソードの独立実装検証器による再現を含む

**なぜ重要か**: 「報酬の情報源がエージェントの証拠収集行動を決定する」という因果結果は、エージェントRL設計の実務指針として極めて価値が高い。LLM判定器の甘さの定量化は報酬ハッキング研究に重要な示唆を与え、事前登録とレプリケーションを備えた研究手法の質も際立っている。

**関連キーワード**: GRPO, 報酬設計, 報酬ハッキング, ツールエージェント, 検証行動, 事前登録

### 4. 再訓練なしでクロスリンガル安全性ドリフトを修復: Safe LoRA vs RESTA比較検証

| 項目 | 内容 |
|------|------|
| ソース | [Hugging Face Community](https://huggingface.co/blog/Aburvan/safetydrift-track-2b2) |
| 公開日 | 2026-11-15 |
| 重要度 | ⭐⭐⭐ |

**概要**: Tiny Aya Fire（3.35B）のファインチューニングによる安全性劣化（safety drift）を英語・ヒンディー語・タミル語・Tanglish（ローマ字コードミックス）で監査し、重み空間修復手法（RESTA vs Safe LoRA）の優劣を統計的に検証した。英語のみの有害データ100件（学習データの14%）の混入で、ヒンディー語・タミル語でも約90%の危険応答に悪化する「クロスリンガル・ドリフト」を確認。Safe LoRA（threshold 0.7）のみがFire同等の安全性を保ちつつタスク性能を維持した。

**詳細ポイント**:
- 2つの独立LLM判定器（Cohere Command A、Llama 3.3 70B）を用い、1,946応答で90%の一致率を確保
- 汚染ファインチューンで危険応答が17%→68〜71%（p < 0.0001）に悪化。多言語モデルは安全機構を言語間で共有している
- RESTAはα=0.5でもドリフトの3分の1しか除去できずタスク性能を破壊。Safe LoRA t=0.7は安全性をFire水準に復元しタスク利得の73%を保持、過剰拒否0%
- TanglishはFire自体を含む全モデルで15〜23%がガベージ応答 — 重み空間修復では埋められない「アライン済みモデルが最初から持たない」ギャップを指摘

**なぜ重要か**: ファインチューニングによる安全性劣化が言語を跨いで伝播することの定量実証は、多言語LLM運用における重大なリスク指摘。再訓練不要の修復手法の優劣を統計的に比較した実践的ベンチマークであり、エンタープライズでのカスタムモデル適用の安全設計に直結する知見。

**関連キーワード**: Safe LoRA, RESTA, 安全性ドリフト, クロスリンガル, LLM-as-Judge, コードミックス

- Gartnerは2026年末までに企業アプリの40%がタスク自律型エージェントを搭載すると予測 — MCPを通じたサイドチャネル攻撃の影響範囲は今後急拡大する
- 攻撃の本質は「悪意あるツールを追加する」のではなく、正規ツールの使い方をエージェントに誤解させることにあり、伝統的なツール検証では防げない
- 既存のツール検証ツール（mcp-scan等）は既知の脅威を検知できるが、ツール記述を通じた文脈汚染には構造的に無力
- 対策として、機密性の高い操作の前にはエージェント本体ではなくアプリケーション層で検証を行うことが推奨される

**なぜ重要か**: エージェント導入が企業アプリの標準機能化するタイミングで、「正規ツールの誤用」という新しい攻撃クラスが実務レベルで指摘された。セキュリティ投資の対象がモデルやツール単体から「エージェントのオーケストレーション層」へ移行すべきことを示す警鐘であり、エンタープライズAIの設計指針に直結する。

**関連キーワード**: MCP, AIエージェントセキュリティ, ツール汚染, プロンプトインジェクション, エンタープライズAI
