### 1. MIT CSAIL、GPT-6 Astraがニューラルネットの重みを「直接読み書き」する Weight-Space Programming を発表 ― 訓練なしでQwen3.5-0.8Bの数学精度を7.9%→48.1%に

| 項目 | 内容 |
|------|------|
| ソース | [MIT CSAIL Blog (Rikiya Takehi)](https://rikiyat.github.io/blog/weight-space-programming/)、[VentureBeat](https://venturebeat.com/technology/like-gene-editing-for-neural-networks-mit-researchers-used-gpt-6-astra-to-edit-qwens-open-weights-directly-boosting-math-performance/)、[AI/TLDR](https://ai-tldr.dev/releases/mit-csail-weight-space-programming/) |
| 公開日 | 2026-11-02 |
| 重要度 | ⭐⭐⭐ |

**概要**: MIT CSAIL の研究チーム(Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab)が「Weight-Space Programming(重み空間プログラミング)」を発表した。OpenAI の GPT-6 Astra がニューラルネットの生の重みをテキストとして読み、各部分の計算内容を推論したうえで、訓練ループなしで重みを直接書き換える。VentureBeat はこれを「ニューラルネットの遺伝子編集」と評し、AIがAIの内部機構を診断・修復する新パラダイムの実証として11月2日に報じた。

**詳細ポイント**:
- Qwen3.5-0.8B の数学問題でのループ癖について、原因方向を層15と19のMLPに特定し、全重みの約0.016%(131,072個)を編集。MATH-500 が7.9%→48.1%、GSM8K が13.8%→67.1%、IFEval が21.0%→62.3%に向上した
- 修正には158回の会話ターン・80回のPython実行・約20.3時間を要した一方、MinAtar Breakout では訓練なしで517.4点のゲームAIネットワークをゼロから記述し、5億ステップ訓練のPPO(25.3点)を大きく上回った
- 限界も公表: 重みだけでは「追従的」Gemma 3 270M のファインチューニング問題を特定できず、同モデルの数学改善にも失敗。「編集は障害を除去できるが、欠けた能力は追加できない」と結論。全1,125ターンのログ・コード・評価データをMITライセンスで公開

**なぜ重要か**: 「データも勾配訓練もなしに、LLMがモデルを監査・修復する」という解釈可能性とモデル保守の新ルートを初めて具体的に示した。バックドア検知、ゼロデータでの能力制御、モデル間モジュール移植など応用が広がる一方、PauseAI CEOが「危険な加速」と警告するように開発速度と安全性の緊張も浮き彫りになった。

**関連キーワード**: Weight-Space Programming, GPT-6 Astra, MIT CSAIL, Qwen3.5, モデル編集, 解釈可能性, Omar Khattab

### 2. 「重みの中のスリーパー」― エージェントにバックドアを植え付け、カーネルだけが検知した実験を FINAL-Bench が公開

| 項目 | 内容 |
|------|------|
| ソース | [HF Community Blog (FINAL-Bench)](https://huggingface.co/blog/FINAL-Bench/the-sleeper-in-the-weights-we-planted-a-backdoor-i) |
| 公開日 | 2026-11-02 |
| 重要度 | ⭐⭐⭐ |

**概要**: FINAL-Bench(VIDRAFT)が、LLMエージェントにおけるバックドア攻撃と防御の実証記事を公開した。エージェント用の小型モデルに意図的にバックドアを植え付け、各防御層の検知能力を検証するもので、「外部の監視では見逃され、カーネルレベルの防御だけが捕捉した」という結果を報告している。前日(11月1日)の提言「ViKernel: キルスイッチはモデルの内側にあるべき」の実証編にあたる。

**詳細ポイント**:
- Qwen3-0.6B ベースのエージェントにバックドアを再現し、通常動作では異常が表面化しない「スリーパー」状態を構築

- 「重みの中に眠るバックドア」は通常のファインチューニング監査では検出困難で、モデル内部での常時検証という設計の必要性を定量的に示した

**なぜ重要か**: エージェントが実務に組み込まれる2026年において、供給網攻撃・バックドアは最重要リスクの一つ。外部ガードレールの限界と「カーネル内防御」の有効性を実験で示したことで、AI安全設計とエージェント運用のガバナンスに直接影響する。

**関連キーワード**: バックドア, エージェントセキュリティ, ViKernel, FINAL-Bench, Qwen3-0.6B, モデル安全性, キルスイッチ

### 3. スライディングウィンドウアテンションは線形アテンションに勝つ ― ただし短い回答に限る(HF Blog研究記事)

| 項目 | 内容 |
|------|------|
| ソース | [HF Community Blog (sirluk)](https://huggingface.co/blog/sirluk/sliding-window-beats-linear-attention) |
| 公開日 | 2026-11-02 |
| 重要度 | ⭐⭐⭐ |

**概要**: Hugging Face コミュニティブログで、スライディングウィンドウアテンション(SWA)と線形アテンションの比較研究記事が公開された。結論は「SWAは線形アテンションに勝つが、それは短い回答に限られる」というもの。長い生成タスクでは両者の優劣が逆転・混在する知見を、蒸留モデルを用いた実験で示している。

**詳細ポイント**:
- 蒸留した Qwen3-4B を用い、SWAと線形アテンションの挙動を短い回答と長い生成で系統的に比較
- 短い回答タスクではSWAが優位に立つ一方、長文生成では線形アテンションが競争力を取り戻すことを確認
- 両者の長所を組み合わせる「Bifocal(二焦点)層」の設計に関する分析・考察を含む

**なぜ重要か**: 「線形アテンション時代」の流行に対する実証的チェックであり、長文コンテキスト全盛の2026年においてアーキテクチャ選定の判断材料になる。蒸留を組み合わせたオープンな検証手法自体も、コミュニティ研究の生産的な形として注目される。

**関連キーワード**: スライディングウィンドウアテンション, 線形アテンション, Bifocal, Qwen3-4B, 蒸留, アーキテクチャ研究

- 数千ツールをコンテキストに読み込む非効率を解消する「Omni MCP」でインクリメンタルな探索・スキーマ取得・選択的呼び出しを可能にし、Response Projection でエージェントが必要な応答フィールドだけを要求できる。業界からは「API ゲートウェイの数十年来のパターンと同一」(Pipe17 社長 Kelly Goetsch)という評価も

### 23. OpenAI、Codex規模のpushに耐えるようGitバックエンド「Pando」を再構築 ― 中央値pushレイテンシ80%削減、1日約1PBのGitデータを処理

| 項目 | 内容 |
|------|------|
| ソース | [OpenAI Blog](https://openai.com/index/scaling-git-at-openai/)、[AI/TLDR](https://ai-tldr.dev/releases/openai-pando-git-backend/)、[OpenAI Git フォーク (GitHub)](https://github.com/openai/git)、[HN議論](https://news.ycombinator.com/item?id=50345924) |
| 公開日 | 2026-11-02 |
| 重要度 | ⭐⭐⭐ |

**概要**: OpenAI が、自社モノレポ全体を支える新しい Git 互換バックエンド「Pando」を発表した。Codex エージェントの大量の push・clone で旧システムが限界を迎え(信頼性が一時90%未満、マージ失敗が多発)、Git ホスティングを再構築する必要に迫られた。エンジニアもエージェントも通常の Git クライアントとプロトコルをそのまま使え、利用方法は一切変わらない。

**詳細ポイント**:
- 各 push はイミュータブルな packfile として blob ストアに保存し、メタデータストアがブランチごとの「ref version」を記録。ブランチが独立して更新される因果的一貫性により、無関係なブランチへの push が互いに待たされない
- fetch 時は既存の packfile を使い回し、packfile-uri 機能経由でリージョンキャッシュ(ヒット率99%超)から配信。バックグラウンドのコンパクションが小 pack を統合(LSM ツリーと同型)
- 中央値 push レイテンシは約80%削減、1日あたり約1PB の Git データを処理。Pando 自体は Codex とともに10週間で Rust で書かれ、GPT-6 Astra エージェントが書いた Lean・TLA+ モデルで検証。技術公開も検討中

**なぜ重要か**: 「コーディングエージェントが人間チームよりはるかに多いブランチ・push・clone を生む」というエージェント時代の開発インフラ限界を、最前線の実データで示した初めての事例。開発インフラの再設計需要と、AI によるシステム構築(Rust+Lean/TLA+検証)の実用例の双方が示された。
